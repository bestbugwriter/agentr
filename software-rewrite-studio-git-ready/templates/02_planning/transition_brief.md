# Transition Brief

## Target
Copilot-like 安卓个人财务助手

## Why now
- iOS 端已有成熟的高付费个人财务产品范式
- Android 端在“高级聚合视图 + 自动洞察 + 美观体验”上仍有明显空白
- 用户愿意为净资产跟踪、预算控制、账单提醒、订阅管理这类高频价值持续付费

## Core wedge
第一阶段不做“全量银行基础设施平台”，而是先做：
1. 多账户资产总览
2. 净资产趋势
3. 预算与现金流洞察
4. 订阅识别与账单提醒
5. AI 财务摘要与异常提示

## Target user
- 已经在认真管理个人财务的中高收入个人用户
- 有多账户、多信用卡、储蓄与投资管理需求的用户
- 愿意为更好的视图、提醒和洞察付费，而不是只想要免费记账的人群

## MVP recommendation
### 必做
- 账户与资产录入/同步入口
- 统一净资产面板
- 月度现金流视图
- 预算分类与超支提醒
- 订阅识别与到期提醒
- AI 财务周报 / 月报摘要

### 暂不做
- 高复杂度税务能力
- 高频交易与券商级投资分析
- 家庭多人协作账本
- 自动报销与企业财务场景

## Key risks
1. 数据接入复杂度高，银行/账户聚合方案会直接影响体验
2. Android 上是否真的存在足够强的高客单付费意愿，还需要继续验证
3. 财务类产品对信任感和隐私安全要求高
4. 过早扩展到投资分析会导致 MVP 失焦

## Evidence status
### 已官方验证
- iOS 上存在成熟个人财务与净资产跟踪产品形态
- 该类产品普遍采用订阅制，并围绕净资产、预算、现金流、提醒构建价值

### 部分验证
- Android 端在“高质量个人财务助手”方向存在体验和品牌空白
- 用户愿意为自动洞察与更好的财务总览持续付费

### 未完全验证
- Android 用户是否愿意接受与 iOS 同等级的高端定价
- 最优的数据接入策略是否应在 MVP 就做真实聚合，还是先从半手动方案切入
- 订阅管理与预算洞察哪一个更应成为第一主打卖点
