# Working Conventions

## Keep stages explicit
Do not blur research, evaluation, planning, and packaging into one undifferentiated run.
Move forward only when the current stage output is strong enough.

## Prefer stable artifacts
Write outputs into stable, reusable document shapes.
Prefer updating a known artifact over inventing a new ad hoc structure every time.

## Evidence before confidence
If pricing, platform coverage, feature scope, or user willingness to pay is still unclear, say so explicitly.
Do not convert weak evidence into a strong planning recommendation.

## Package neutrally first
When preparing work for coding shells, create the shell-neutral task package first.
Only then render host-specific prompts such as Codex or Claude Code variants.

## Commit cleanly
Keep commits narrow and stage-based.
A good repo history should make it easy to see:
- what was researched
- what was selected
- what was planned
- what was packaged for execution
