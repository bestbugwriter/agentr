# MVP 规划指南

## 功能分层

### 必做
满足核心价值验证所需的最小功能集合。

### 可选增强
能提升体验，但不影响首轮商业验证。

### 不做
会拖慢上线，且对验证价值不大。

## 取舍原则
- 优先验证“有人愿不愿意付费”，再验证“能不能做得极致”。
- 能用现成服务解决的，不先自研。
- 能人工兜底的环节，不必一开始自动化到底。
- 避免为了边缘场景堆复杂度。

## 任务拆解规则
- 一个任务对应一个清晰产出。
- 任务描述要能直接给 AI coding agent 执行。
- 每个任务都写验收标准。

## 风险提示
规划时至少检查：
- 数据来源是否稳定
- 法律与平台风险是否可控
- 关键体验是否依赖难以替代的外部能力
- 单位经济模型是否说得通
