# Selected Opportunity Evaluation

## One-line conclusion
`AI visual bug reporting copilot` 值得继续，最适合的切口不是“再做一个大而全的 QA 平台”，而是做一个更轻、更快、更便宜的浏览器内 AI bug writer。

## Opportunity rating
- Grade: `A`
- Weighted score: `84 / 100`

## Why it ranks first
- `官方价格已证明付费成立`：Jam、Marker.io、BugHerd 都把浏览器内 bug capture 做成了明确的付费工作流。
- `工作流高度集中`：截图、录屏、页面上下文、控制台与网络日志，本身就是一个很清晰的单一闭环。
- `AI 的价值直接命中人工痛点`：AI 不只是“加聊天框”，而是能把原始捕获整理成工程团队真正需要的 ticket。
- `个人开发者可切入`：Chrome 扩展 + 小型 SaaS + 单一导出集成，足够做出能收费的 MVP。

## Key supporting reasons
- `官方验证完整`：价格、浏览器扩展分发、核心能力和浏览器支持都能回到官网或官方 listing。
- `切口清楚`：不是做全量 QA 平台，而是做“把原始反馈变成开发可用 ticket”的 AI 层。
- `适合单兵作战`：先只接 GitHub，先做录屏或截图二选一，先做 Chrome，再扩到 Edge/Brave。

## Main risks
- `隐私与脱敏`：一旦采集敏感页面数据，安全感不足会直接阻断采用。
- `竞品拥挤`：如果没有明确聚焦在更便宜、更快、更干净的 issue 输出上，会被中大厂功能面压住。
- `集成预期`：团队往往很快就会要 Jira、Linear、Slack、SSO，这些需求会拉散 MVP。

## Evidence status
- `已官方验证`：定价、扩展分发、浏览器支持、核心能力。
- `部分验证`：用户痛点密度、最优目标客群、最敏感的隐私顾虑强度。
- `未完全验证`：一个全新独立品牌是否能在低销售动作下拿到首批付费团队；小团队更偏好截图流还是短录屏流。
